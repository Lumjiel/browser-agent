## 当前讨论目标

在 Android Termux proot 容器中部署 DeepSeek Harness (dsh) —— 原生模块修复失败，需要讨论完整替代方案。

### 当前状态

已验证通过：
- Node.js v26.4.0 ✅
- pnpm install ✅
- build:lib:host + client ✅

失败：
- node-pty: Termux 没有 Android NDK，无法编译
- koffi: statx 类型不兼容（Bionic libc vs glibc），即使 API Level 30 也无法编译
- sharp: 缺少 libvips

官方 Termux 方案（GitHub Discussion #136）失败原因：
- android_ndk_path 补丁 + API Level 30 对 koffi 的 statx 类型错误无效
- 这是 koffi 源码层的 Android 适配问题，不是编译参数能解决的

### 被否定的方案

- 方案1（修原生模块）: koffi 源码层类型不兼容，需要 patch 源码，工作量大
- 方案2（改 dsh 源码）: 之前被评为 ⭐，但现在可能是唯一可行路径
- 方案3（写 Cordis 插件）: 被评为 ⭐⭐，维护成本极高

### 核心困境

base bundle 的 cordis.patch.yml 加载的是 sandbox 版本插件：
- subprocess → dsh-subprocess-local（依赖 node-pty）
- sandbox → dsh-sandbox-local（依赖 koffi）
- bash-sandbox → dsh-bash-sandbox
- fs-sandbox → dsh-fs-sandbox

local 版本（dsh-bash-local、dsh-fs-local）存在但不被 base bundle 加载。

尝试用 cordis.patch.yml 禁用沙箱后，tool-bash 找不到 shell 服务挂起。
尝试用 patch 新增 bash-local 条目但似乎不支持。

### 需要讨论的核心问题

1. 修改 base bundle 的 cordis.patch.yml 是否真的不可行？
   - 把 subprocess 从 subprocess-local 改为其他实现？
   - 把 bash-sandbox 改为 bash-local？
   - 把 fs-sandbox 改为 fs-local？
   
2. 或者有没有第四种方案：创建一个"Android bundle"替代 base bundle？
   - 复制 base bundle → 替换 sandbox 为 local → 新建 profile 引用它

3. 修改源码后的长期维护策略：
   - 如何追踪上游更新？
   - 如何最小化 merge conflict？
   - 是否需要 git branch 管理？

4. 最关键的问题：在放弃沙箱安全性后，dsh 在 Android 上的实际运行效果如何？
   - 没有 sandbox 的 tool-bash 是否正常工作？
   - 没有 sandbox 的 tool-fs 是否正常工作？
   - 没有 subprocess 的 tool-fs-search 是否降级？
